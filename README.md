# «Мозг-администратор» Анастасии Карташовой

Операционная база портфеля и локальная панель. Владелица принимает решения; мозг-администратор держит общую картину; проекты и профильные роли исполняют поручения в своих границах.

## Быстрый запуск

Пошаговая установка, проверка, запуск сервера и доступные интеграции: [runtime README](system/runtime/README.md). Локальная панель отвечает внутри рабочей среды по `http://127.0.0.1:8787/`; это loopback-адрес, не доступный из браузера владелицы. Для просмотра портфеля из файлов проекта откройте [статическую сводку](system/portfolio-overview.html); обновите её командой `python system/build-portfolio-view.py`.

## Межпроектная работа

- Чтобы сразу увидеть портфель и все задачи одним файлом: [визуальная сводка портфеля](system/portfolio-overview.html). Это обновляемый снимок; запуск `python system/build-portfolio-view.py` собирает страницу из реестров CSV.
- Текущий статус и план интеграции всех рабочих источников: [центр интеграций](system/integration-center.md). Проверены реальные коннекторы, локальная база и ограничения прямой синхронизации; задачи пакетного переноса отмечены в общем реестре.
- Практическая инструкция «как обмениваться данными с общей базой»: [общая база проектов](system/shared-base-guide.md). Текущий режим — ручной handoff из отдельных GPT-проектов и Perplexity в центральный чат Codex; прямой синхронизации нет.
- Значимые идеи/решения из других GPT-чатов передавать в [общий входящий поток](system/idea-handoff.md); карточки и маршрутизация хранятся в [реестре идей](system/ideas.csv). Автоматической синхронизации GPT-проектов сейчас нет.
- Проекты, задачи, решения, источники, CRM музыки и роли хранятся в CSV и локальной SQLite; ограничения интеграций указаны в [матрице доступа](system/data-access.md).
- Роли: [секретарь](system/agents/secretary-of-day.md), [маркетолог](system/agents/marketing-strategist.md), [редактор статей](system/agents/content-editor.md), [Продажник](system/agents/sales-agent.md), [Критик здравого смысла](system/agents/strategic-critic.md) и остальные в [реестре ролей](system/roles.csv). Это инструкции и маршруты для работы, не фоновые автономные сотрудники.
- [Анкета владельца](system/owner-profile-questionnaire.md) учитывает уже известные данные и собирает недостающий коммерческий профиль. [Передача исследования из Perplexity](system/external-research-handoff.md) описывает текущий ручной процесс: Perplexity-коннектор не найден.
- Для read-only проверки, чего уже хватает для выводов по воронке/доходам и чего недостаёт, см. [аудит аналитической готовности](system/analytics/README.md) и текущий [отчёт](system/analytics/portfolio-readiness.md). Без данных о лидах, фактических поступлениях и расходах аналитический сервис не может вывести реальную экономику.
- Первая продажная линия: [P11 Avito](system/projects.csv), [карта каналов](system/sales-channel-plan.md) и цель P02; роль Продажника сравнивает Avito, HeadHunter, фриланс-площадки и прямые источники. Данные Avito/HH пока не переданы, а фриланс-площадки — гипотеза до исследования.
- [Карта отделов](system/departments.md) задаёт ответственность за продажи/продвижение, маркетинговое исследование, HR-исполнение, редакцию, финансы и портфель; [план развития функций](system/learning-plan.md) фиксирует навыки, упражнения и нужные данные.
- [Черновые маскоты](system/mascots.md) дают игровой образ ролям, не вводя новый сервис или расходы.

Главные ориентиры, решения и границы — в [обзоре портфеля](system/overview.md), [операционной модели](system/operating-model.md) и [30-дневном цикле](system/30-days.md). Доходные цифры — цели, не прогноз. Внешние сообщения, публикации, платные расходы и решения о цене остаются за Анастасией.
