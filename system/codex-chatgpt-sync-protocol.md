# Обязательный протокол взаимодействия Codex ↔ ChatGPT
Дата решения: 2026-10-27. Владелица: Анастасия Карташова.

## Цель
Все проекты и принятые решения должны иметь одну проверяемую актуальную версию. Codex и ChatGPT должны использовать общий источник, не требуя от владелицы повторного изложения решений.

## Реальные ограничения
GitHub даёт доступ к файлам, но не к полным историям чужих чатов. Автоматическая межчатовая синхронизация пока НЕ настроена; создание файла не означает её запуск. Не обещать мгновенной передачи и не называть неувиденный документ полученным.

## Порядок работы
1. Источник версий и обмена: этот репозиторий, далее — защищённая база событий. Все проекты из system/projects.csv входят в охват, не только продюсерский центр.
2. Каждое утверждённое решение — отдельная запись: event_id, project_id, created_at (с timezone), source (Codex или ChatGPT), источник/ссылка, тип (решение/задача/факт/гипотеза), текст, версия, затронутые проекты, утверждение владелицы, статус доставки. Повторы по ID и версии не создавать.
3. Перед работой проверять последнюю доступную версию решений; после работы публиковать новое принятое решение через доступный механизм и проверять чтением, что запись появилась. Если запись не удалась — честно обозначить статус.
4. Codex отвечает за техническую реализацию и фиксацию архитектурных изменений; ChatGPT — за координацию, контекст и анализ. Оба не вправе самостоятельно менять решения владелицы, цены, расходы или ставить на запуск приостановленные проекты.
5. Конфликт версий фиксировать, не перетирать содержимое. Личные данные, тексты закрытых договоров, резюме и ключи доступа НЕ выкладывать в публичный репозиторий.

## Первая задача реализации
Создать двусторонний защищённый транспорт событий: источник изменений → очередь/webhook → авторизованная база → подтверждение доставки, проверка дублей и ошибки. Провести тест Codex → база → ChatGPT и ChatGPT → база → Codex. Пока чтение истории чатов через официальный интерфейс не доступно, синхронизировать именно опубликованные структурированные решения и файлы, не все реплики.

## Согласованный план внедрения
Порядок утверждён владелицей 2026-11-04 и уточнён 2026-11-09. Целевая база для постоянной работы — Supabase-проект `kartashova-brain`. Уже существующий `kartashova-brain-test` — тестовый стенд: он не пустой, к нему подключено приложение Timeweb и в нём есть рабочие данные. Новый тестовый проект не создавать. Не переходить к переключению на основной проект, пока не проверены данные, схема и восстановление.

1. **Зафиксировать текущие подключения.** Timeweb использует `kartashova-brain-test`; Codex MCP и основная интеграция должны работать с `kartashova-brain`. Project refs и секреты не записывать в публичные файлы.
2. **Проверить интеграции.** ChatGPT Supabase app после переподключения видит оба проекта; её наличие не означает, что уже настроен ограниченный обмен. Учитывать, что у приложения заявлены права чтения и записи.
3. **Использовать существующий тестовый стенд.** Проверять изменения в `kartashova-brain-test`; не создавать ещё один стенд, не сбрасывать и не удалять существующие данные.
4. **Провести сравнительный аудит схемы и безопасности.** Сопоставить таблицы, ограничения, RLS и права тестового и основного проектов. Уже известны таблицы приложения и предупреждения Supabase Advisor в тестовом проекте; выяснить реальные grants и политики до изменения RLS. Предыдущий просмотр основного проекта не обнаружил таблиц в `public`; перепроверить это перед переносом.
5. **Спроектировать журнал и план переноса.** Определить event ID, проект, тип, источник, время с часовым поясом, версию, содержимое, подтверждение владелицы, статус доставки и идемпотентность. Сначала проверить схему на существующем стенде; конечное размещение — в основном проекте.
6. **Реализовать узкий транспорт с минимальными правами.** Не использовать широкие права Supabase app/MCP для постоянной записи событий. Ограничить операции журналом, закрыть доступ без авторизации и хранить секреты только в защищённой конфигурации.
7. **Перенести и переключить приложение на основной проект.** До переключения сделать и проверить резервную копию тестовых данных, подготовить схему и сопоставить записи. После переноса проверить API, Telegram и оба направления обмена GPT ↔ Codex. Порт приложения напрямую в интернет не открывать.
8. **Сохранить откат и закрепить основной проект везде.** Оставить тестовый стенд нетронутым до подтверждения восстановления и устойчивой работы основного проекта. Настроить ChatGPT, Codex MCP и Timeweb на `kartashova-brain`; среду Codex Cloud вести отдельно, поскольку она не создаёт общий транспорт.

**Текущий статус:** пункты 1–3 выполнены. Следующий шаг — пункт 4: аудит существующих схем и прав двух проектов без чтения содержимого записей и без изменений в базе.
