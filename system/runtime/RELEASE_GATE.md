# Пусковой контроль синхронизации · 2026-11-20

Статус: **НЕ ГОТОВО К ПРОДАКШЕНУ**. Это не отчёт о выполненной автоматической синхронизации.

## Результаты, подтверждённые CI

- Журнал событий, проверки версий/конфликтов, авторизация API и ACK.
- Ограниченный вход синтетических GitHub webhook-событий.
- Одноразовые, неактивные по умолчанию адаптеры Github и Supabase REST.
- Применение SQL-схемы к одноразовому PostgreSQL в CI (не Supabase).
- HTTP-контракт, секреты не помещаются в URL.
- Локальный HTTP-тест (GitHub HMAC → SQLite queue → authenticated ACK).

## Подготовлен запуск Codex по GitHub label

`.github/workflows/codex-synthetic-task.yml` — ограниченный workflow, который
после размещения в default branch сможет выполнять `openai/codex-action@v1`
только для открытых Issue, созданных владельцем и помеченных владельцем
`codex-approved`. Задание читает один заранее заданный файл, работает с
`sandbox: read-only` и `safety-strategy: drop-sudo`; текст Issue в prompt
не передаётся. API-ключ берётся исключительно из GitHub Actions secret
`OPENAI_API_KEY`. При его отсутствии Codex не запускается. Этот workflow
сейчас НЕ АКТИВИРОВАН в `main`; он НЕ способен самостоятельно запускать
пользовательские задачи и не создаёт долговременную сессию Codex.

Для реального исполнения потребуется отдельно настроить API billing и
`OPENAI_API_KEY` (подписка ChatGPT сама по себе не равна API-кредитам),
принять связанные расходы, подтвердить разрешения GitHub Actions и
пройти один контролируемый тест. Не записывайте токен в Issue/README.

## Блокеры до объединения с main

1. **Supabase security:** в проекте `kartashova-brain-test` семь таблиц
   `public` имеют RLS=false. Исправление политик требует аудита доступа,
   иначе риск раскрытия данных или нарушения работы. Нельзя использовать
   существующий проект для тестов до устранения блокера или выделения
   другого полностью изолированного проекта.
2. Отсутствует подтверждённый реальный тест Supabase Data API
   с серверными секретами, минимальными привилегиями, write/read-back.
3. Нет автоматики, которая доставляет результат GitHub в отдельные
   чаты ChatGPT и Codex. Issue и ACK не являются такой доставкой.
4. Не настроено непрерывное выполнение queue worker и защита от
   конкурентных воркеров/двойных публикаций.
5. Нет итогового сквозного теста в облаке и проверки наблюдаемости,
   восстановления после сбоев, ограничений расходов и бэкапов.
6. Timeweb не подключён и production deployment не проверен.

## Разрешённый порядок запуска

1. Проверить и согласовать политики RLS/минимальные права, изолировать тестовую базу.
2. На отдельном проекте только с синтетическими записями протестировать Supabase API.
3. Ограничить расходы на API, проверить секреты, разрешить конкретный test Issue.
4. Объединять с `main` только после review и изолированного сквозного теста;
   слияние само по себе не является разрешением на production deploy.
5. Включить мониторинг, аварийное отключение и документированный rollback,
   только затем развёртывание сервиса.

Не помещать резюме кандидатов, контакты, договоры, токены или приватную
переписку в публичный GitHub. Никакие реальные базы, серверы или секреты
этим документом не изменены.
