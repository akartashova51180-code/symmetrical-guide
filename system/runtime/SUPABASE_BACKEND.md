# Подключение ядра к Supabase

## Что нужно системе

| Компонент | Назначение | Статус |
| --- | --- | --- |
| Supabase PostgreSQL | Проекты, задачи, решения, лиды, финансы, каталог песен и очередь уведомлений | Код поддерживает PostgreSQL через `CORPORATE_BRAIN_DATABASE_URL`; действующее подключение к проекту ещё не настроено |
| Python API | Панель и операции с реестрами | Реализован в FastAPI; привязан к loopback и не имеет собственной аутентификации |
| Telegram-приёмщик | Запись идей/песен и команды владельца | Реализован; для запуска нужны токен бота, числовой ID владельца и постоянно работающий процесс |
| Планировщик/уведомления | Сводки и задачи по расписанию, очередь повторной отправки | Реализованы в приложении; работают, пока запущен постоянный сервер |
| Файлы песен | Аудио, тексты, обложки и экспорты | Сейчас хранятся на постоянном диске приложения, не в Supabase Storage |
| Supabase Auth / Edge Functions / Realtime | Публичный вход, отдельные серверные функции, мгновенные обновления браузера | Для текущей личной версии не нужны: API остаётся приватным, логика уже исполняется в Python |

## Важное разделение

- Hosted Supabase MCP — административный доступ агента к проекту для проверки. MCP пока не авторизован в Codex.
- `CORPORATE_BRAIN_DATABASE_URL` — подключение работающего приложения к PostgreSQL. Это отдельная настройка, не создаваемая MCP.
- `read_only=true` для MCP не переводит приложение в read-only режим. При запуске FastAPI приложение выполняет `CREATE TABLE`/добавочную миграцию и, если реестр `records` пустой, импортирует CSV из `system/`. Поэтому до первого запуска на Supabase надо проверить схему и данные и явно утвердить миграцию/начальный импорт.

## Подготовленная схема развёртывания

`deploy/compose.supabase.yml` запускает API и Telegram-приёмщик, используя внешнюю PostgreSQL-базу Supabase вместо контейнера Postgres. Файл `deploy/.env.supabase.example` содержит только имена переменных и подсказки, без секретных значений. Скопируйте его на сервер как `.env` только после проверки схемы и согласования начального запуска.

Для подключения приложению нужен PostgreSQL URI из Supabase Dashboard → **Connect**. URI выбирается для PostgreSQL, а не `anon` или `service_role` API key. Для TLS используйте `sslmode=require`; если сервер не имеет IPv6, обычно подходит Supavisor **Session pooler**. Пароль базы хранится только в закрытом `.env` на сервере или в секрет-хранилище хостинга. Не передавайте URI в чат и не вставляйте его в Git.

Файлы песен остаются в `/srv/anastasia-brain/data/assets`; этот каталог надо сохранять вместе с базой и резервировать. Supabase Storage можно добавить позже, если нужен обмен медиа без постоянного диска приложения; это потребует приватного bucket, правил доступа и отдельного ключа, поэтому сейчас он не подключён.

Панель не имеет входа по паролю. Не публикуйте порт `8787` в Интернет: он выставлен только на `127.0.0.1` для доступа через VPN или SSH-туннель. Telegram ограничивается `TELEGRAM_ALLOWED_USER_IDS`. Если потребуется публичная веб-панель или несколько пользователей, сначала добавляется аутентификация и разграничение доступа; одного наличия Supabase Auth недостаточно, пока приложение не интегрировано с ним.

## Read-only MCP из локального Codex

Для первого просмотра схемы используйте локальный Codex на том же компьютере, где откроется браузер авторизации. Не запускайте OAuth-вход в удалённой облачной shell-сессии и не присылайте сюда redirect URL/callback: он содержит одноразовый код входа.

Минимальный URL MCP для проекта:

```text
https://mcp.supabase.com/mcp?project_ref=<PROJECT_REF>&read_only=true&features=database%2Cdocs
```

В PowerShell на компьютере с Codex CLI проверьте `codex --version`. Если CLI уже установлен, добавьте MCP с этим URL (подставив project reference локально), затем запустите вход с ограниченными read scopes:

```powershell
codex mcp add supabase --url "https://mcp.supabase.com/mcp?project_ref=<PROJECT_REF>&read_only=true&features=database%2Cdocs"
codex mcp login supabase --scopes organizations:read,projects:read,database:read
codex mcp list
```

Вход и браузерный callback должны выполняться на одном компьютере. После статуса `Authenticated` откройте новую Codex-сессию и проверяйте только список проекта/таблиц и чтение схемы. Если CLI сообщает, что `supabase` уже настроен, не удаляйте его наугад: сначала проверьте `codex mcp get supabase`. На время проверки не снимайте `read_only=true` и не расширяйте список OAuth scopes.

Если OAuth завершается ошибкой про MCP resource/project reference, остановитесь. В открытых сообщениях есть такой случай; временное удаление `project_ref` расширяет видимость до проектов аккаунта и не должно применяться автоматически.

## Что осталось проверить

1. Успешно войти в Supabase MCP из локального Codex (обход публикации Codex Cloud) и проверить проект/схему read-only.
2. Подтвердить, что проект пустой или согласовать план сопоставления его существующих таблиц с реестрами приложения.
3. В защищённом окружении сервера задать `CORPORATE_BRAIN_DATABASE_URL`; не добавлять его в Codex MCP или Git.
4. Только после явного разрешения выполнить и проверить инициализацию схемы и начальный импорт CSV.
5. Отдельно перенести API/бот на постоянный сервер, внести секреты Telegram, пройти личный тест и проверить резервное восстановление.
