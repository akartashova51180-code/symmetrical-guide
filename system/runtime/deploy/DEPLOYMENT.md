# Развёртывание на личном сервере: PostgreSQL + CRM + Telegram

Инструкция рассчитана на один VPS с Ubuntu 24.04 LTS и одного владельца. Система использует PostgreSQL для рабочих данных, отдельный каталог на диске для аудио и документов, веб-приложение для портфеля, Telegram-приёмщик и Telegram-уведомления. Один экземпляр приложения запускается одним worker-процессом: несколько копий сейчас запускать нельзя, иначе расписание может сработать несколько раз.

В репозитории уже подготовлены PostgreSQL-совместимый слой хранения, перенос SQLite → PostgreSQL, Dockerfile и Compose-файл. Тесты проходят; схема, очередь и импорт данных проверены на временном PostgreSQL. Это ещё не означает, что система уже размещена на сервере: для реального переноса нужны VPS, его адрес и приватный доступ к репозиторию. Приложение пока не имеет входа по паролю, поэтому панель должна оставаться доступной только через частную VPN-сеть или SSH-туннель. Порт приложения и PostgreSQL не открывайте публично.

## Сначала проверить на своём Windows-компьютере

Для предварительного личного теста PostgreSQL и Docker не нужны: приложение запустится с локальной SQLite. Нужны файлы проекта, Python 3.12, `uv`, доступ в Интернет к Telegram и отдельный тестовый бот. Если изменения ещё не появились в GitHub, сначала перенесите актуальные файлы на компьютер; обычный `git clone` пока может скачать старую версию.

Откройте PowerShell в корневой папке проекта и перейдите в runtime:

```powershell
Set-Location "C:\путь\к\symmetrical-guide\system\runtime"
uv --version
uv sync --locked --extra test
if (-not (Test-Path .\deploy\.env)) { Copy-Item .\deploy\.env.example .\deploy\.env }
notepad .\deploy\.env
```

В `deploy\.env` заполните токен тестового бота. Пока оставьте ID пустыми. Файл `.env` исключён из Git; не копируйте его в переписку, GitHub или общий диск.

Откройте тестового бота в Telegram и нажмите **Start**. Пока API и приёмщик ещё не запущены, в PowerShell получите ID только из ожидающего личного `/start`:

```powershell
uv run --env-file deploy/.env python -m corporate_brain.telegram_owner_id
```

Скрипт отправит запрос Telegram API с вашей машины и выведет ID пользователя и его Telegram username; токен не печатает. Если появится несколько ID, в `.env` вносите только свой. Запишите ID и в `TELEGRAM_ALLOWED_USER_IDS`, и в `TELEGRAM_NOTIFY_CHAT_ID`, сохраните `.env`.

Оставьте это окно PowerShell работающим с API:

```powershell
uv run --env-file deploy/.env uvicorn corporate_brain.app:app --host 127.0.0.1 --port 8787
```

Откройте **второе** окно PowerShell, снова перейдите в `system\runtime` и запустите Telegram-приёмщик:

```powershell
Set-Location "C:\путь\к\symmetrical-guide\system\runtime"
uv run --env-file deploy/.env python -m corporate_brain.telegram_intake
```

При старте бот зарегистрирует командное меню в Telegram. Вернитесь в диалог и отправьте `/start`. Проверьте «Сводка», «Проекты», «Задачи», запись тестовой идеи, создание тестовой песни и прикрепление небольшого разрешённого аудиофайла. Эти данные попадут в локальную базу `system\runtime\data\`; для теста используйте копию проекта, чтобы не смешивать тестовые записи с рабочими. Завершить оба процесса можно сочетанием `Ctrl+C` в каждом окне.

Этот локальный запуск работает только пока открыты оба окна и включён компьютер. Он нужен для личного прогона и демонстрации; круглосуточную работу даст отдельный VPS с Docker Compose из следующих разделов. Docker на Windows для SQLite-прогона не нужен.

## 1. Подготовить VPS

В панели выбранного провайдера создайте сервер с Ubuntu 24.04 LTS. Для старта одного пользователя разумная отправная точка — 2 vCPU, 4 GB RAM и диск от 40 GB; место нужно увеличивать по мере накопления аудиомастеров и резервных копий. Регион выбирайте с учётом того, где разрешено хранить ваши рабочие и клиентские данные. Цена, надёжность и правила хранения зависят от провайдера; их нужно проверить до покупки.

При создании сервера добавьте ваш SSH-ключ. Если ключа ещё нет, создайте его на своём компьютере:

```bash
ssh-keygen -t ed25519 -a 100
```

Закрытый файл ключа оставьте на своём устройстве. В панели сервера задайте firewall: SSH (порт 22) доступен только с вашего IP, если провайдер это позволяет. Не открывайте наружу 5432 (PostgreSQL) и 8787 (панель/API). Вход через 443 понадобится только при отдельной настройке внешнего HTTPS-доступа; ниже описан более закрытый VPN-путь.

Подключитесь по SSH способом, который выдал провайдер:

```bash
ssh ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_СЕРВЕРА
```

Сразу обновите систему:

```bash
sudo apt update
sudo apt upgrade -y
```

Установите Docker Engine и Compose plugin по актуальной инструкции Docker для Ubuntu с официального сайта. Затем проверьте:

```bash
docker --version
docker compose version
sudo systemctl enable --now docker
```

Не добавляйте пользователя в группу `docker` без необходимости: доступ к этой группе практически равен root-доступу. Ниже команды Docker показаны с `sudo`.

## 2. Получить файлы приложения

Создайте каталог сервера и загрузите репозиторий. Если репозиторий закрытый, для сервера используйте отдельный read-only SSH deploy key; не вставляйте GitHub-токен в URL или командную строку.

```bash
sudo mkdir -p /srv/anastasia-brain
sudo chown "$USER":"$USER" /srv/anastasia-brain
git clone git@github.com:akartashova51180-code/symmetrical-guide.git /srv/anastasia-brain/repo
```

Если код ещё не отправлен в репозиторий, сначала зафиксируйте и отправьте на GitHub текущую версию либо передайте файлы по SSH. Не добавляйте к коммиту `.env`, `portfolio.sqlite3`, аудио, токены или резервные копии.

Создайте постоянные каталоги данных и копий:

```bash
sudo mkdir -p /srv/anastasia-brain/data /srv/anastasia-brain/backups
sudo chown 10001:10001 /srv/anastasia-brain/data
sudo chmod 750 /srv/anastasia-brain/data
sudo chmod 700 /srv/anastasia-brain/backups
```

Пользователь приложения внутри контейнера имеет UID 10001. Каталог `/data` должен быть доступен для него на запись, иначе загрузка файлов не сработает.

## 3. Создать Telegram-бота и безопасно задать секреты

В Telegram откройте `@BotFather`, создайте отдельного бота и скопируйте токен сразу в защищённый файл конфигурации на сервере. Узнайте свой числовой Telegram user ID. Токен не присылайте в этот чат, не отправляйте письмом и не добавляйте в Git.

Перейдите в каталог развёртывания и создайте закрытый `.env`:

```bash
cd /srv/anastasia-brain/repo/system/runtime/deploy
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

Вставьте полученную случайную hex-строку в `POSTGRES_PASSWORD`. Заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_IDS` своим числовым ID, `TELEGRAM_NOTIFY_CHAT_ID` тем же ID и `DATA_ROOT=/srv/anastasia-brain/data`. Hex-пароль выбран потому, что он безопасен для строки подключения PostgreSQL без URL-кодирования. Файл `.env` не должен попадать в Git или резервную копию без шифрования.

До запуска откройте личный чат с новым ботом и нажмите `/start`. Тогда Telegram разрешит боту отправлять вам личные сообщения. Бот принимает только private-чат владельца из allowlist и игнорирует остальных.

## 4. Безопасно подготовить перенос SQLite

Не копируйте работающий файл `portfolio.sqlite3` обычным `cp`: в активном режиме SQLite может хранить последние записи в файле WAL рядом с базой. Используйте SQLite Backup API, который формирует согласованный снимок. Из корня репозитория на исходной машине выполните:

```bash
cd system/runtime
uv run --locked python -m corporate_brain.backup_sqlite_snapshot \
  --source data/portfolio.sqlite3 \
  --output /tmp/portfolio.sqlite3
```

Если `uv` ещё не установлен, установите его по официальной инструкции или создайте снимок Python 3.12 и установленным окружением проекта. Скрипт делает `integrity_check` снимка. Для строгой согласованности данных остановите API и бота на время финального снимка; затем скопируйте также папку `data/assets/`, если в ней есть загруженные файлы.

Передайте snapshot и каталог медиа на VPS по SSH. Например, из локальной машины:

```bash
scp /tmp/portfolio.sqlite3 ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_СЕРВЕРА:/srv/anastasia-brain/data/portfolio.sqlite3
rsync -a system/runtime/data/assets/ ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_СЕРВЕРА:/srv/anastasia-brain/data/assets/
```

Если папки `assets` нет, пропустите вторую команду. Для контроля передачи посчитайте SHA-256 снимка на обеих машинах командой `sha256sum` и сравните значения. SSH шифрует канал передачи. После импорта исходный снимок и первоначальную копию медиа не удаляйте до проверки приложения и резервной копии PostgreSQL.

В текущем рабочем окружении база лежит в исключённом из Git каталоге `system/runtime/data/`; она не отправляется на GitHub при обычном `git push`. Файл SQLite может быть меньше соседнего `-wal`, поэтому переносить нужно именно через подготовленный snapshot, а не выбирать один файл из папки вручную.

## 5. Поднять PostgreSQL и импортировать данные

На сервере проверьте, что `.env` заполнен и каталог данных принадлежит UID 10001. Затем, всё ещё в `/srv/anastasia-brain/repo/system/runtime/deploy`, проверьте Compose без вывода секретов:

```bash
sudo docker compose --env-file .env -f compose.yml config --quiet
```

Соберите образы и запустите **только** базу данных:

```bash
sudo docker compose --env-file .env -f compose.yml build
sudo docker compose --env-file .env -f compose.yml up -d db
sudo docker compose --env-file .env -f compose.yml ps
```

Не запускайте `app` до импорта: при пустой PostgreSQL базе приложение может загрузить CSV из репозитория, после чего импорт SQLite правильно откажется писать в непустую целевую базу.

Выполните разовый перенос. Целевая PostgreSQL база должна быть пустой. Файл snapshot и папка `assets` уже должны лежать в `/srv/anastasia-brain/data/`:

```bash
sudo docker compose --env-file .env -f compose.yml run --rm --no-deps app \
  python -m corporate_brain.migrate_sqlite_to_postgres \
  --source /data/portfolio.sqlite3 --data-dir /data
```

Команда переносит реестры, решения, задачи, карточки песен, состояния приёмщика, расписание и очереди, затем сверяет SHA-256 каждого файла CRM. Импорт не удаляет и не изменяет исходный SQLite snapshot. Старые уведомления не рассылаются все подряд; актуальная на дату переноса сводка может быть поставлена в очередь.

Если команда сообщит, что PostgreSQL не пуст, остановитесь и выясните, какие данные уже записаны. Не удаляйте таблицы автоматически. Если не найдены медиафайлы или не совпал SHA-256, исправьте копирование файлов и повторите миграцию в пустую БД.

## 6. Запустить круглосуточное приложение и бота

После успешной миграции запустите приложение и Telegram-приёмщик:

```bash
sudo docker compose --env-file .env -f compose.yml up -d app telegram-bot
sudo docker compose --env-file .env -f compose.yml ps
```

Проверка API выполняется на самом сервере; порт опубликован только на loopback:

```bash
curl --fail --silent http://127.0.0.1:8787/healthz
curl --fail --silent http://127.0.0.1:8787/api/summary
```

В ответе `/healthz` ожидается `status: ok`; сверьте числа проектов, задач, песен, доходов, pipeline и вложений с исходной базой. Команда `docker compose ps` должна показывать `db`, `app` и `telegram-bot` как запущенные; `app` должен стать healthy.

Откройте Telegram-бота и нажмите `/start`. Проверьте кнопки и отправьте `/help`; не отправляйте секреты и клиентские данные в тесте. Для загрузки пробного файла используйте отдельную учебную карточку и разрешённый к экспорту тестовый материал. Бот в ответ должен показать ID карточки. Затем отдельно проверьте получение планового уведомления, см. раздел ниже.

Контейнеры настроены с `restart: unless-stopped`, поэтому Docker запустит их после перезагрузки VPS. Docker также включён через `systemctl enable`. После перезагрузки проверьте:

```bash
sudo docker compose --env-file .env -f compose.yml ps
```

Планировщик работает внутри единственного процесса приложения. Не добавляйте `--workers 2` и не запускайте вторую копию API: это создаст повторные расписания.

## 7. Получать уведомления в Telegram

В Compose уже предусмотрена отправка сообщений. Она использует три настройки из `.env`:

- `TELEGRAM_BOT_TOKEN` — секрет бота;
- `TELEGRAM_ALLOWED_USER_IDS` — разрешённый числовой ID;
- `TELEGRAM_NOTIFY_CHAT_ID` — личный chat ID, который должен совпадать с ID из allowlist.

Уведомления формируются так:

- ежедневная сводка портфеля и задач — в 09:00 по Москве;
- отдельные напоминания о сроках сегодня и просроченных задачах;
- повестка недели — в понедельник, среду и пятницу.

При свежем запуске приложения цикл проверяет портфель сразу, затем повторяется каждый день. Новые сообщения сначала сохраняются в PostgreSQL outbox. Если Telegram временно недоступен, приложение повторяет отправку каждые 5 минут. После успешной отправки запись отмечается, чтобы перезапуск не присылал одно уведомление повторно. Если токен не задан или chat ID не разрешён, отправка не выполняется; проверяйте `sudo docker compose ... logs app` и записи запусков планировщика. В сводке показывается количество внесённых записей дохода, а пустой финансовый реестр отдельно помечается — бот не выдаёт его за подтверждение нулевого дохода.

Это пока не мгновенный мониторинг любого изменения: новые просрочки и сводка проверяются по расписанию, а не при каждом редактировании карточки. При необходимости можно отдельно добавить уведомления при создании или изменении конкретных типов задач.

## 8. Открыть панель только себе

По умолчанию Compose публикует приложение на `127.0.0.1:8787` внутри VPS. Ни один внешний пользователь не должен обращаться к `http://АДРЕС_СЕРВЕРА:8787`.

Для разовой проверки удобно сделать SSH-туннель со своего компьютера:

```bash
ssh -L 8787:127.0.0.1:8787 ИМЯ_ПОЛЬЗОВАТЕЛЯ@АДРЕС_СЕРВЕРА
```

Пока SSH-соединение открыто, на своём компьютере откройте `http://127.0.0.1:8787`. Для ежедневного доступа настройте частную VPN-сеть (например, Tailscale/WireGuard) и разрешите доступ к серверу только вашим устройствам и аккаунту. Веб-приложение пока не имеет собственной авторизации; до добавления пароля не публикуйте его в общий интернет и ограничьте доступ ACL VPN. Telegram-бот не требует входящих портов: он сам опрашивает Telegram и отправляет исходящие сообщения.

## 9. Резервные копии и восстановление

PostgreSQL хранит метаданные; песни, ZIP-экспорты и другие файлы лежат в `/srv/anastasia-brain/data/assets`. Нужны обе части копии. Для разовой ручной проверки выгрузите базу:

```bash
sudo docker compose --env-file .env -f compose.yml exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \
  > /srv/anastasia-brain/backups/postgres-$(date +%F).dump
```

И сохраните медиа отдельным архивом:

```bash
sudo tar -czf /srv/anastasia-brain/backups/assets-$(date +%F).tar.gz \
  -C /srv/anastasia-brain/data assets
```

Копии на том же VPS защищают от случайной ошибки, но не от поломки диска или потери VPS. Передавайте ещё одну копию на отдельное хранилище по зашифрованному каналу и шифруйте её отдельно; ключ расшифрования храните вне сервера. Не кладите `.env` рядом с незашифрованными копиями.

В репозитории есть скрипт для ежедневных зашифрованных архивов PostgreSQL и медиа с хранением 30 дней. На сервере установите `age` из доверенного пакета Ubuntu и создайте ключ на своём личном компьютере, не на VPS:

```bash
age-keygen -o ~/brain-backup-identity.txt
age-keygen -y ~/brain-backup-identity.txt
```

Сохраните приватный `brain-backup-identity.txt` отдельно от сервера, например в защищённом менеджере паролей и ещё одной офлайн-копии. Возьмите строку `age1...` из второй команды — это публичный ключ, его можно хранить на VPS.

Скопируйте скрипт и unit-файлы:

```bash
sudo install -o root -g root -m 0750 /srv/anastasia-brain/repo/system/runtime/deploy/backup.sh /usr/local/sbin/backup-anastasia-brain
sudo install -o root -g root -m 0644 /srv/anastasia-brain/repo/system/runtime/deploy/backup.service /etc/systemd/system/backup-anastasia-brain.service
sudo install -o root -g root -m 0644 /srv/anastasia-brain/repo/system/runtime/deploy/backup.timer /etc/systemd/system/backup-anastasia-brain.timer
sudo nano /etc/anastasia-brain-backup.env
```

В файл `/etc/anastasia-brain-backup.env` добавьте каталоги и публичный ключ, но не приватный:

```text
BRAIN_DEPLOY_DIR=/srv/anastasia-brain/repo/system/runtime/deploy
BRAIN_DATA_ROOT=/srv/anastasia-brain/data
BRAIN_BACKUP_DIR=/srv/anastasia-brain/backups
AGE_RECIPIENT=age1ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
```

Затем ограничьте права, выполните пробную копию и включите расписание:

```bash
sudo chown root:root /etc/anastasia-brain-backup.env
sudo chmod 600 /etc/anastasia-brain-backup.env
sudo systemctl daemon-reload
sudo systemctl start backup-anastasia-brain.service
sudo journalctl -u backup-anastasia-brain.service --no-pager -n 30
sudo systemctl enable --now backup-anastasia-brain.timer
systemctl list-timers backup-anastasia-brain.timer
```

Резервные файлы создаются в каталоге backups с расширением `.age`; скрипт удаляет старые архивы старше 30 дней. Перед отправкой на отдельное хранилище проверьте, что архив расшифровывается приватным ключом на вашем личном компьютере, и периодически тестируйте восстановление в отдельную тестовую базу/каталог. Не удаляйте первоначальную копию миграции, пока новый backup не проверен.

## 10. Обновление и контроль работы

Сначала создайте проверенную резервную копию. Затем обновите репозиторий и приложение:

```bash
cd /srv/anastasia-brain/repo
git pull --ff-only
cd system/runtime/deploy
sudo docker compose --env-file .env -f compose.yml build
sudo docker compose --env-file .env -f compose.yml up -d
sudo docker compose --env-file .env -f compose.yml ps
```

Для диагностики используйте:

```bash
sudo docker compose --env-file .env -f compose.yml logs --tail=100 app telegram-bot db
```

Проверяйте статус контейнеров, время последней утренней задачи, заполнение диска, успешность резервной копии и факт доставки сообщения `/start`/планового уведомления. Токены и строки подключения не копируйте в обращения за помощью.

## Что эта схема пока не синхронизирует

Сервер и бот не получают автоматически историю других Telegram-ботов, чаты GPT/Perplexity, письма, Avito, HeadHunter или соцсети. Для каждого источника нужен экспорт, официальный API/коннектор или отдельная разработка. Telegram здесь служит личным входом для ручной передачи песен и каналом уведомлений, а не универсальным сборщиком всех переписок.
