# Ядро «Мозг-администратор» 0.2

Исполняемый контур: общая база для портфеля и песен, API, рабочая панель и ежедневный планировщик в 09:00 по Москве. По умолчанию используется SQLite для локального режима; для серверного режима поддерживается PostgreSQL через `CORPORATE_BRAIN_DATABASE_URL`. Все медиа остаются в отдельном постоянном каталоге `CORPORATE_BRAIN_DATA_DIR`; проекты связываются с песнями по ID. Кампании продвижения и расходы на AI/Telegram-сервисы — отдельные реестры со ссылками на общий каталог.

## Установка и запуск

Требования: Python 3.12 и uv. Из `system/runtime`:

```bash
uv sync --locked --extra test
uv run --locked uvicorn corporate_brain.app:app --host 127.0.0.1 --port 8787
```

При первом локальном запуске импортируются CSV из `system/`. База и загруженные файлы хранятся в `system/runtime/data/`, каталог исключён из Git. Для другого места задайте `CORPORATE_BRAIN_DATA_DIR`; для другого каталога исходных реестров — `CORPORATE_BRAIN_SOURCE_DIR`. Если задан `CORPORATE_BRAIN_DATABASE_URL`, таблицы создаются в PostgreSQL вместо файла SQLite. На сервере сначала перенесите SQLite-снимок командой `python -m corporate_brain.migrate_sqlite_to_postgres`; не запускайте пустое приложение раньше импорта, иначе оно импортирует CSV в новую базу.

Проверка: откройте корень локального сервиса или выполните `curl http://127.0.0.1:8787/healthz` и `curl http://127.0.0.1:8787/api/summary`.

API привязан к localhost: в этой версии нет входной аутентификации. Не меняйте host на `0.0.0.0` и не выставляйте его в Интернет.

## Единая CRM песен

`creative-catalog.csv` и реестр `music_songs` — общий каталог для всех проектов. Одна песня имеет один ID `Cxx` и может быть связана с P04, P06, P09 «Вселенная Москвы» и/или P10 «Продвижение песен». Каталоги по проектам не дублируются. Метаданные сохраняют название и тип, проектные связи, сторонний AI-сервис/Telegram-бот, ссылку/ID генерации, даты и версии, исходные файлы, участников и согласия, проверку лицензии платформы, права, бриф и публикации.

- `GET /api/music/songs`, `GET /api/music/campaigns`, `GET /api/music/costs` — каталог, кампании и затраты.
- `POST /api/music/music_songs` с JSON `{"fields":{"название":"...","связанные_проекты":"P09;P10"}}` создаёт один паспорт; `PATCH /api/music/music_songs/{song_id}` меняет его поля.
- `POST /api/music/song_campaigns` создаёт кампанию, ссылающуюся на существующий `song_id` и проект. План и факт ведутся отдельно; публикации сервис сам не выполняет.
- `POST /api/music/music_costs` фиксирует оплату AI/Telegram-сервиса. Подписку учитывайте как один платёж за период, не копируйте полную сумму на каждую песню.
- В панели есть формы создания паспорта, кампании и расходов, а также загрузки файлов к выбранному song ID.
- `POST /api/music/songs/{song_id}/assets` принимает файл и тип: `audio_master`, `instrumental`, `stem`, `lyrics`, `cover`, `source_export` или `other`. Разрешены WAV, MP3, M4A, FLAC, OGG, AAC, AIFF, MIDI, TXT, PDF, DOCX, ZIP, PNG, JPG; предел — 100 МБ. Сохраняются имя, размер, дата и SHA-256. Повтор той же суммы байтов в одной песне не создаёт копию.
- `GET /api/music/songs/{song_id}/assets` и `GET /api/music/assets/{asset_id}` показывают список и отдают файл.

## Приём генераций из платного Telegram-бота

### Сразу доступный ручной путь

В генераторе скачайте разрешённый к экспорту файл, откройте локальную панель, создайте паспорт песни с названием, связанными проектами, названием бота, датой и ссылкой/ID генерации, затем загрузите аудио, текст или исходный экспорт в карточку. Расход на подписку/кредиты добавьте отдельной записью. Новая версия добавляется в тот же паспорт, а не как копия песни. Не переносите в CRM токены, пароли или закрытые переписки.

### Подготовленный Telegram-приёмщик

В модуле `corporate_brain.telegram_intake` подготовлен polling-бот для личного управления портфелем и ручного приёма песен. При `/start` он показывает меню сводки, проектов, открытых задач, записи идеи, каталога песен и создания паспорта. Кнопка новой песни запускает пошаговый ввод названия; затем отправьте файл в активную карточку. Команды: `/summary`, `/projects` (список) или `/projects P09;P10` (связать активную песню), `/tasks`, `/idea`, `/task P02 | Что сделать | 2026-11-01`, `/songs`, `/new`, `/source ИмяБота`, `/link URL`, `/text текст`, `/done`, `/cancel`. Идея из Telegram записывается во входящий поток со статусом классификации; бот сам не принимает бизнес-решение и не назначает идее проект/роль. Новая задача создаётся только с явно указанным проектом. При старте приёмщик устанавливает этот список команд через Telegram Bot API. Несанкционированные ID и групповые чаты игнорируются.

Для реального запуска нужно создать отдельного бота через BotFather, безопасно задать `TELEGRAM_BOT_TOKEN` и личный числовой `TELEGRAM_ALLOWED_USER_IDS`, затем запустить API в одном терминале, а из каталога модуля во втором выполнить:

```bash
uv run --locked python -m corporate_brain.telegram_intake
```

Приёмщик использует исходящий polling к `api.telegram.org`, публичный webhook не нужен. Текущие чаты платных ботов он сам читать не может: Telegram не передаёт новому боту историю другого бота; требуется вручную переслать/скачать результат. Облачный Bot API ограничивает скачивание файла до 20 МБ; для больших мастеров используйте загрузку в веб-панели с пределом 100 МБ. Сначала проверьте правила экспорта и коммерческого использования конкретного AI-сервиса.

### Уведомления Telegram

При задаче расписания приложение формирует в БД суточную сводку, задачи со сроком сегодня/просроченные и недельную повестку понедельника/среды/пятницы. Если заданы `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_IDS` и `TELEGRAM_NOTIFY_CHAT_ID` (chat ID должен входить в allowlist), новые уведомления отправляются в личный чат владельца. Перед этим владелица должна открыть диалог с ботом и нажать `/start`. Уведомления сначала попадают в постоянную outbox-очередь; неотправленные записи повторяются каждые 5 минут. При запуске приложения выполняется суточный цикл и отправка ожидающих записей. Без токена уведомления сохраняются, но не доставляются.

Круглосуточная односерверная схема с PostgreSQL и Telegram описана в [инструкции развёртывания](deploy/DEPLOYMENT.md). Compose-черновики находятся в `system/runtime/deploy/`; доступ к API опубликован только на loopback `127.0.0.1`, не открывайте его или PostgreSQL напрямую в интернет.

## Расходы и доход

`music-costs.csv` хранит фактические платежи генераторам и сервисам; `song-campaigns.csv` — расходы и результаты продвижения. Можно записать общий платёж за подписку или привязать расход к одной работе. Не распределяйте пакетную подписку по песням без подтверждённого метода. Выручка, заказы и метрики требуют фактических доказательств; пустые данные не равны нулевому доходу.

## Планировщик, безопасность и границы

APScheduler создаёт ежедневный цикл в 09:00 Europe/Moscow и повторяет его при запуске сервиса с защитой от дублей. Пока процесс остановлен, расписание и бот не работают. Для непрерывной эксплуатации нужны постоянный хост, аутентификация, шифрование/контроль доступа к файлам, резервное копирование и мониторинг. Локальная версия предназначена для разработки и личного использования; не публикуйте её в Интернет. Email, календарь, Avito, HeadHunter, соцсети и другие GPT-проекты не синхронизированы. Выгрузки из них передаются владельцем. Внешние публикации, расходы и клиентские сообщения требуют отдельного решения владелицы.

OpenAI Agents SDK скачан отдельно, но не подключён: ключ и разрешённые внешние инструменты ещё не заданы.

## Входящий поток идей и межпроектная маршрутизация

Итог обсуждения из любого отдельного GPT-чата владелица или участник передаёт через «Входящий поток» на панели либо шаблон `system/idea-handoff.md`. Запись хранится в общем реестре `ideas.csv` и SQLite как `Ixx`, получает статус «На классификацию» и сохраняет источник, факты, гипотезы, решение владелицы, затронутые проекты и роли. Панель позволяет сохранить маршрут и обоснование.

Классы: общая установка для портфеля; тема конкретного проекта — только его куратору и относящимся к теме ролям; гипотеза — на проверку; нерелевантная/личная запись — «Не требует действия» или архив. Это не рассылает данные в другие GPT-чаты и не запускает фоновых агентов: маршрутизированная запись и назначенная роль становятся видны в общей системе, а выполнение происходит по запросу/заданию.

Роль автора статей называется **Редактор контента и автор статей** (`content_editor`). Редактор пишет и адаптирует утверждённые черновики; профильные кураторы и маркетолог дают предметный контекст и проверяют аудиторию. Площадки, заявленные владелицей: Одноклассники, TenChat, Telegram и ВКонтакте; Facebook используется для пересылки из TenChat, но владелица пока не может войти туда с компьютера. Аккаунты и показатели не подключены/не проверены, публикация не автоматизирована.

- `GET /api/ideas` — общий входящий поток.
- `POST /api/ideas` с `{"fields":{"идея":"...","источник_проект":"P03","источник_чат_GPT":"..."}}` — новая запись на классификацию.
- `PATCH /api/ideas/{Ixx}` с `{"fields":{"статус":"Передано в проект","влияние_на_проекты":"P03","маршрутизация":"content_editor; market","обоснование_маршрута":"..."}}` — сохранить маршрут и круг затронутых ролей.

## Продажи, маркетинг, финансы и отделы

Продажник отвечает за коммерческое продвижение, каналы, поиск/квалификацию лидов и движение сделки; маркетолог исследует покупателя, критерии выбора и рыночные факты; финансовый аналитик оценивает экономику только на фактических суммах. Редактор и творческие роли производят материалы в поддержку коммерческой цели, публикация требует решения владелицы.

P11 содержит первичную гипотезу проверки Avito. HeadHunter — канал, названный владельцей, но статистики нет. Фриланс-площадки в [карте каналов](../sales-channel-plan.md) — кандидаты для проверки, не подтверждённые источники клиентов. Распределение отделов и ответственности: `system/departments.md`; развитие практических инструкций: `system/learning-plan.md`; черновые маскоты: `system/mascots.md`.

## Продуктовая мастерская

`system/product-opportunities.csv` импортируется в общий реестр как `product_opportunities` и показывается на панели в блоке «Продуктовая мастерская». P12 по безопасности предприятия поставлен первым в текущей продуктовой очереди по поручению владелицы; он связан с P01 и остаётся гипотезой до изучения издания «Директор по безопасности», подтверждения покупательского запроса и согласования участия/ответственности партнёра. Задачи можно назначать роли `product` («Искра — архитектор новых продуктов»). Чтобы новая карточка появилась в API, нужен импорт `POST /api/import` или перезапуск с автоимпортом при старте.
