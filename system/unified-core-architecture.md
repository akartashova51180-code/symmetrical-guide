# P00 · Единое ядро и обмен данными · архитектурный контракт v0.1
Решение владелицы: 27.10.2026. Приоритет: P0. Статус: проектирование и внедрение; не считать синхронизацию запущенной до end-to-end тестов.

## Единый механизм, а не набор чатов
Единственным операционным источником истины должна стать защищённая серверная база PostgreSQL, развернутая из уже созданного Python-ядра `system/runtime`. GitHub — источник версий **кода, схем и очищенных от приватных данных решений**, но не база персональных сведений, закрытых документов или аудиофайлов. Защищённое объектное хранилище — для оригиналов и файлов; записи в PostgreSQL хранят идентификаторы, версии, хеши и ссылки на доступ. CSV — импорт/экспорт, но не второй writable master.

## Потоки
1. ChatGPT / Codex / поддерживаемый плагин / разрешённый бот → аутентифицированный ingress API.
2. Ingress → валидация проекта/прав/согласования → транзакция PostgreSQL: event + обновление сущности + outbox. Событие имеет event_id (уникальный), entity_id, project_id, aggregate_version, source_system, source_ref, occurred_at, actor, classification, visibility, approval_status, payload_hash, correlation_id.
3. Outbox → подписчики и адаптеры (с повтором, журналом ошибок, дедупликацией по event_id), затем delivery receipt / cursor.
4. Чтение от любого клиента → GET snapshot+version + изменения after_cursor. При несовпадении версии — конфликт, а не тихая перезапись.
5. GitHub: CI/CD, код, спецификации, технические issues и неперсональные проектные решения. Commit/PR содержит project ID и ссылку на событие. Не трактовать issue как доставленное сообщение в Codex-сессию.
6. Полная история частных ChatGPT/Codex-чата не доступна автоматически одним лишь GitHub-подключением. Если отсутствует официально доступный API передачи событий чата, использовать только поддерживаемые интеграции для **опубликованных решений**, честно показывая покрытие и задержку.

## Обязательные контуры
- P00: портфель, задачи, решения и интеграции.
- Все ID из system/projects.csv (не ограничиваться перечисленными), отдельные пространства/права проектов.
- P04/P06/P09/P10: единый каталог произведений, versions, audio assets, rights, campaign and cost ledgers. Импорт двух больших пакетов Codex/Nousha без потерь и дубликатов; содержимое не считать увиденным, пока источник не доступен.
- Юридический департамент продюсерского центра: юридические записи и документы в **закрытом хранилище**; структуру/полномочия брать только из исходного утверждённого решения Codex.
- Маркетинг, HR, продуктовая мастерская и остальные отделы: независимые роли на общей базе с минимальным доступом.

## Этапы реализации
A. Read-only backup SQLite и snapshot CSV, инвентаризация файлов и прав, проверка оригинального Codex-пакета; ничего не стирать.
B. Миграция данных в PostgreSQL с проверкой количества записей, уникальности ID, связей и контрольных сумм; повторный импорт идемпотентный.
C. Реализовать authn/authz, roles, tenant/project isolation, event/outbox/delivery tables, POST ingress и GET snapshot/changes, журнал аудита, backups.
D. Подключить 1 пилотный поток ChatGPT→API→Codex и 1 Codex→API→ChatGPT при наличии поддерживаемых точек интеграции; иначе проверять механизм на тестовых клиентах и явно оставлять «автоматизация чатов не доступна».
E. При успешном пилоте — добавлять коннекторы только для нужных каналов. Каждый коннектор: разрешения, объём, стоимость/лимиты, дата последней успешной синхронизации, ошибка и revoke.
F. Пользовательская панель: сводка проектов, статус синхронизации по источникам, missing source, conflict, failed delivery; переключение контуров при едином ядре.

## Приёмка (без снижения требований)
- На разных клиентских точках открывается **один и тот же** project snapshot/version.
- Двусторонние события доставляются, подтверждаются, повторы не дублируют записи; офлайн-клиент догоняет через cursor.
- Ссылки на реальный исходный пакет Codex/Nousha, все найденные произведения, юридические и маркетинговые решения сопоставлены без выдуманных сведений.
- В публичном GitHub нет исходников закрытых договоров, персональных данных и секретов.
- Система показывает, какие источники не подключены. Никаких заявлений об автоматическом чтении полных чатов без действующего API.
- Паузы, цены, юридические утверждения, публикации и расходы меняет только владелица или явно уполномоченная роль.
