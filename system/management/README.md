# Мозг-администратор · шесть управленческих задач

**Срез подготовки:** 20.11.2026. **Статус:** рабочий управленческий пакет на утверждение, не автоматический доступ к другим GPT-чатам.

Цель: создать действующую управленческую систему для проектов Анастасии, а не подменять бизнес-задачи разработкой интеграций. Основные источники: `system/projects.csv` (13 паспортов P00–P12), `system/tasks.csv` (23 исходных записи), `system/operating-model.md`, `system/overview.md`, `system/30-days.md`, `system/analytics/portfolio-readiness.md`. Все данные текущих проектов, не внесённые туда, требуют фактической сверки; пустая финансовая запись означает отсутствие записи, **не** отсутствие продаж. Суммы и сроки без документального подтверждения не называются фактом.

## Правило работы

1. **Владелица** решает, какую услугу продавать, кому писать, цену, бюджет, приоритеты и обязательства.
2. **Мозг-администратор** ведёт единый проектный ID, очередь действий, подтверждения, блокеры, план/факт и еженедельный обзор.
3. **Профильные роли** готовят материал и результат, но не выступают независимо от владелицы.
4. P02 — привлечение HR-заказчиков; P08 — исполнение конкретных вакансий. Заявку считать коммерческой только после верификации прямого заказчика и условий.
5. Персональные данные кандидатов, конфиденциальные коммерческие сведения, семейные данные и ключи не помещать в публичный GitHub.
6. Вся автоматизация ChatGPT/GitHub/Codex/Supabase — отдельный технический трек; её готовность не подменяет фактические данные продаж.

## Первый рабочий обзор

- **Сейчас:** сверить активные обязательства P08, собрать фактические статусы клиентских заявок в защищённой системе, затем начать бесплатную проверку прямого B2B-спроса.
- **Каждый день:** 3–4 часа именно на привлечение/маркетинг/бренд; не путать с временем исполнения рекрутинговых заказов.
- **Каждую неделю:** новые прямые компании → подтверждённые брифы → предложения → договорённости → поступившие оплаты; отдельно часы и расходы; отдельно консультационные запросы.
- **Первый продукт:** первичная гипотеза в `06-first-offer.md`, не считать утверждённым тарифом.
- **Главные риски:** нет в общей базе текущей выручки/конверсии, не подтверждён состав активных клиентских заказов, тестовая Supabase имеет критическую проблему доступа (7 таблиц без RLS). Не включать на ней синхронизацию приватных данных.

**Не сделано:** публичные публикации, обращения к клиентам, списания, перенос личных сведений, внедрение системы в `main` или сервер. Это отдельные действия, требующие санкционирования.
