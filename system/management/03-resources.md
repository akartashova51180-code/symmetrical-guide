# 3. Ресурсный аудит: использовать имеющееся, не покупать лишнего

Категории: **подтверждено** (проверенные файлы/подключения), **по сообщениям владелицы** (без live-проверки), **не подтверждено** (нельзя включать в базовую инфраструктуру). Срез 20.11.2026.

| Ресурс/навык | Основание | Статус | Управленческое решение |
|---|---|---|---|
| HR-экспертиза, поиск и оценка специалистов, управление подбором | Описан опыт и есть рабочие проекты | Используемый ресурс | Применить к первому B2B-офферу; результаты кейсов подтверждать |
| Коммерческие контакты / каналы HR | Владелица использует Avito, HH, Telegram, LinkedIn | По сообщениям владелицы; цифры не внесены | Собирать контакты/ответы только с разрешения, хранить закрыто |
| GitHub `symmetrical-guide` | `main`: проекты P00–P12 и задачи T01–T23 | Подтверждено | Источник открытых обезличенных паспортов/регламентов; не хранилище персональных данных |
| Codex / ChatGPT | Рабочие сессии и отдельный черновой технический PR | Инструменты доступны, межчатовая автоматика не работает | Использовать для подготовки/ревью; не обещать автономное исполнение |
| Supabase `kartashova-brain` | Проверена доступность проекта | `public` без таблиц на момент проверки | Не вводить рабочие данные без доступа и схемы |
| Supabase `kartashova-brain-test` | Проверены 7 таблиц без RLS | Критический риск | Не использовать для клиентских/кадровых данных; отдельный аудит политик |
| Timeweb VPS | Один рабочий VPS по указанию владелицы | Сведения владелицы; конфигурация не проверена | Не заказывать второй VPS, не переносить без причины |
| Существующее локальное FastAPI/SQLite ядро | Код и документация в `system/runtime` | Есть реализация; доступность пользователю не подтверждена | Не подменять факт запуска наличием кода |
| Музыкальные материалы и права | Есть отдельные проекты и наработки | Каталог/права не полностью подтверждены | Прежде коммерческой передачи инвентаризация и проверка прав |
| Бюджеты на рекламу/подписки | Нет подтверждённого согласованного лимита | Неизвестно | 0 новых платных сервисов до отдельного утверждения |
| Сводка коммерческих лидов и денег | `portfolio-readiness.md` фиксирует пустые записи на исторический срез | Недостаточно данных | Отсутствие записи не считать нулевой выручкой |
| Клиентские договоры / гарантия / отчётность | Различаются по заказчику и вакансии | Требует сверки | Не публиковать; вести в закрытом реестре с подтверждением |

## Порядок закрытия дефицитов ресурсов

**Без покупок:** (1) собрать анонимные итоги активных заявок; (2) сверить существующие коммерческие предложения; (3) восстановить 2–3 подтверждаемых кейса; (4) снять статистику текущих каналов; (5) упорядочить общий каталог ссылок/решений; (6) только затем решать об интеграциях.

## Красные флажки

- Публичный GitHub не предназначен для персональных данных кандидатов, условий закрытых договоров, семейного контекста или сервисных ключей.
- Не использовать Supabase-test с выключенной RLS как безопасный CRM-источник.
- Не включать автоматический платный API или новую инфраструктуру без подтверждённой экономической необходимости.
- Не считать рекламные охваты и просмотры доказательством востребованности платной услуги.
