# 3. Ресурсный аудит: использовать имеющееся, не покупать лишнего

Категории: **подтверждено** (проверенные файлы/подключения), **по сообщениям владелицы** (без live-проверки), **не подтверждено** (нельзя включать в базовую инфраструктуру). Срез 20.11.2026.

| Ресурс/навык | Основание | Статус | Управленческое решение |
|---|---|---|---|

## Порядок закрытия дефицитов ресурсов

**Без покупок:** (1) собрать анонимные итоги активных заявок; (2) сверить существующие коммерческие предложения; (3) восстановить 2–3 подтверждаемых кейса; (4) снять статистику текущих каналов; (5) упорядочить общий каталог ссылок/решений; (6) только затем решать об интеграциях.

## Красные флажки

- Публичный GitHub не предназначен для персональных данных кандидатов, условий закрытых договоров, семейного контекста или сервисных ключей.
- Не использовать Supabase-test с выключенной RLS как безопасный CRM-источник.
- Не включать автоматический платный API или новую инфраструктуру без подтверждённой экономической необходимости.
- Не считать рекламные охваты и просмотры доказательством востребованности платной услуги.


## Проверка исходных реестров Codex · 20.11.2026

Проверены текущие файлы `main`:

- `system/music-costs.csv` содержит заголовки без записей о платежах. Это означает «расходы не внесены в этот реестр», а не «расходов не было».
- `system/song-campaigns.csv` также содержит только заголовки; фактические расходы и результаты кампаний по песням в базе не зафиксированы.
- `system/social-sources.csv` содержит восемь источников. Часть ссылок не открывалась из среды, часть площадок обозначена только со слов владелицы; сопоставимых метрик просмотров, целевых обращений и оплат в реестре нет.
- `system/pipeline.csv` и `system/income.csv` без записей. На основании этого нельзя утверждать, что вне репозитория не было лидов, расходов или поступлений.
- Снимок `system/analytics/portfolio-readiness.md` датирован 23.10.2026 и не является обновлённым финансовым срезом на 20.11.

**Статус ресурсного аудита:** структура реестров и отсутствие внесённых фактов подтверждены; фактические счета/расходы, доступность рекламных кабинетов и коммерческая эффективность каналов остаются неизвестны. Требуется доступ к соответствующим отчётам или счетам владельцы, без размещения конфиденциальных платёжных сведений в публичном GitHub.
