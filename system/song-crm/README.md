# Единая CRM песен

## Одно хранилище, отдельные проекты

Каталог `creative-catalog.csv` и таблица `music_songs` в SQLite — единый источник паспортов песен для всего музыкального портфеля. Проекты не заводят собственные копии каталога: они ссылаются на один song ID. Сейчас в реестре пять подтверждённых владелицей работ: гимны Мурманска, Тамбова, Ржева, Сталинграда и Клинского мясокомбината. Их наличие известно из сообщения владелицы; аудиофайлы, ролики, версии, условия сторонних AI-сервисов и цепочки прав ещё предстоит проверить.

`P09 «Вселенная Москвы»`, `P06 «Гимны городов»`, `P10 «Продвижение песен»` и музыкальная студия `P04` — самостоятельные проектные карточки. Поле `связанные_проекты` у песни перечисляет контексты работы, но сама карточка хранится только один раз. Кампания в `song-campaigns.csv` связывается с песней через `song_id` и с проектом через `project_id`. Публикация и запуск рекламы требуют отдельного разрешения владелицы.

## Паспорт песни

Одна строка каталога — одна песня/произведение. Идентификатор `Cxx` постоянный. Паспорт фиксирует название, тип, проектные связи, где и когда создана генерация, ссылку/ID внешнего проекта, текст и его версию, аудио-мастер/минус/стемы, авторов и участников, согласия, дату проверки лицензии платформы, цепочку прав, бриф/заказчика и результаты продвижения. Неизвестные сведения оставляются пустыми или со статусом «Проверить»; факты не восстанавливаются по догадке.

Бинарные файлы загружаются к записи песни в локальное хранилище ядра. Файл получает ID, тип (мастер, минус, стем, текст, обложка, экспорт исходного сервиса), размер, контрольную сумму и дату загрузки. Имя оригинала сохраняется, удаление через MVP-интерфейс не предусмотрено. В этой версии размер файла ограничен 100 МБ, разрешены распространённые аудио/текстовые/архивные форматы. База и файлы лежат локально; общая доступность между устройствами появится только после защищённого постоянного хостинга и резервного копирования.

## Рабочий приём генерации из стороннего Telegram-бота

### Доступно сейчас: ручной приём через CRM

1. В чате оплаченного бота скачайте результат на устройство: аудио и, если сервис выдаёт, текст/обложку/архив стемов. В рабочую систему переносите только материалы, которые сервис разрешает экспортировать и использовать.
2. В панели откройте «Добавить песню» и заполните название (или временное рабочее имя), тип, связанный проект, имя стороннего сервиса/Telegram-бота, дату и ссылку/ID генерации. Не вставляйте секретные ключи, личные токены или приватную переписку целиком.
3. Сохраните карточку. CRM выдаст ID Cxx. Добавьте к ней аудиофайлы/текст с корректными типами. При следующем изменении версии обновите тот же паспорт и загрузите новую версию; прежний файл остаётся в истории файлов.
4. Запишите оплату в реестре расходов как отдельный платёж: подписка/пакет кредитов/разовая генерация, сумма, валюта, дата, период и подтверждение. Месячную подписку не приписывайте целиком каждой песне; метод распределения фиксируйте отдельно, если позднее понадобится считать себестоимость.
5. Когда песня будет готова к продвижению, добавьте кампанию, указав тот же song ID, P10 или другой проект, канал и согласование. Сначала записывайте план, затем факт публикации и метрики; система сама ничего не публикует.

### Возможная автоматизация позже

Можно завести отдельного Telegram-бота-приёмщика, которому владелица вручную пересылает результат или отправляет скачанный файл; он направляет аудио и метаданные в API общей CRM. Это не подключит текущие чаты к платным ботам автоматически: обычный Telegram Bot API не предоставляет новому боту историю чужого диалога или возможность читать сообщения других ботов. Для автоматизации потребуется создать отдельного бота, выдать ему токен через защищённые настройки, держать приёмник на постоянном HTTPS-хосте и протестировать лимиты передачи реальных файлов. Токен не передавать в чат или CSV. Если генератор предлагает официальный API/webhook/export, его оценивают отдельно по правилам сервиса и доступным метаданным.

## Платежи и доказательства

## Массовая инвентаризация двух Telegram-каналов

Для первичного разбора не нужно скачивать песни по одной. Предпочтительный вход — два отдельных экспорта Telegram Desktop с медиафайлами: для каждого канала экспортируйте историю чата в JSON и включите медиа; если JSON недоступен, подойдёт HTML. Сохраните экспорты раздельно, например `channel-1.zip` и `channel-2.zip`. Не присылайте пароль или код входа. Перед передачей удалите личную переписку и чужие данные, не относящиеся к песням.

Обработка идёт пакетами: (1) список файлов и контрольные суммы; (2) группировка по сообщению, подписи, времени и именам файлов в предполагаемые комплекты одной песни; (3) предварительное связывание текста, основной версии, альтернатив, инструментала/«нулёвки», стемов и исходного экспорта; (4) очередь неоднозначных связей для проверки Анастасией; (5) создание или обновление одной карточки Cxx на произведение и прикрепление материалов к ней. Манифест сохраняет исходный канал, дату, ID сообщения и имя файла. Близость сообщений — подсказка, а не доказательство общей песни.

Локальная подготовительная автоматизация уже создана: `python system/song-crm/import_telegram_export.py /путь/к/папке/экспортов --output /путь/к/манифесту.csv`. Положите распакованные экспорты обоих каналов в одну родительскую папку; скрипт найдёт JSON экспорты, сопоставит медиа с сообщениями, проверит пути и рассчитает SHA-256. Он работает локально и только для чтения: ничего не отправляет и не меняет. Результат — единый CSV для проверки и дальнейшего пакетного связывания с карточками Cxx.

CRM сейчас принимает файлы по одному в карточку и ограничивает каждый 100 МБ. Поэтому пакетная выгрузка Telegram ещё не является пакетным импортом в CRM: сначала разбираем экспорт целиком и формируем манифест, затем переносим одобренные комплекты. Тип «инструментал» поддерживается. «Нулёвка» неоднозначна: исходную подпись сохраняем, а тип отмечаем «требует классификации», пока Анастасия не подтвердит значение.

Качество не оценивается автоматически одним баллом: фиксируем статус версии (основная / альтернатива / черновик / отклонена / проверить), оценку Анастасии и причину. Технический анализ звука может помочь с сортировкой, но не заменяет её решение о творческой удачности.

## Платежи и доказательства

`music-costs.csv` хранит фактические расходы на ботов, подписки и кредиты; `song-campaigns.csv` — расходы и результаты продвижения. Выручка по заказам должна быть подтверждена отдельно от просмотров. Поля бюджета, просмотров и оплат не заполняются предположениями. Платёжная история пока не передана и не является финансовой аналитикой.

## Границы текущей работы

Общая база, формы создания песни/кампании/расхода и локальная загрузка файлов работают в едином сервисе. Связи между разными GPT-проектами автоматом нет: известные данные нужно передать вручную через карточку/шаблон. Telegram-бот, постоянное облачное хранилище, внешняя авторизация, совместный доступ, бэкапы и синхронизация пока не подключены. После получения названия генератора и примеров его экспорта можно проверить, что можно автоматизировать безопасно.
